# 三源晨报配置

更新：2026-10-19。

## 语音入口与内容

先唤醒“小爱同学”，再说“早报”。也兼容“开始晨间播报”“早间播报”“晨间播报”。

顺序：上海天气与出行建议 → 36氪 → 财经网 → 环球网 → 今天的日程。

- 36氪：AI、科技、公司与商业。
- 财经网：宏观经济、市场与产业。
- 环球网：国际动态、全球经济和科技；区分报道与评论。
- 每家最多三条。只接受原文可读取、可核对发布时间、发布时间在检索时刻之前24小时内的新闻。
- 只有读到并核对官方人气榜前三位置、三篇原文均符合时间范围时，才称“官方人气榜前三”；其他情况标为“近24小时重点新闻”，当前后备顺序按可核实发布时间排列，并非热度排名。
- 对取得的候选新闻按URL、相近标题及事件描述跨站去重，少于九条是正常情况，不用旧闻凑数。模型生成的事件归一化存在误判或漏判可能，不代表已完成全面事实交叉核查。
- 天气、每家新闻、日程分别提交语音播报，单段失败不主动中止后续段；小米内容审核仍可能拒绝某段，当前播报接口不能可靠返回具体审核原因，不保证音箱每段均会发声。
- 仅语音触发，没有定时任务；不汇总提醒事项。

## 归档与隐私

新闻标题、原文链接、发布时间、摘要与天气保存在 Obsidian：`小爱语音/晨报/YYYY-MM-DD HHMMSS 晨报.md`。

不保存完整新闻文章；不把日历内容、Obsidian 私人笔记或原有模型聊天历史送入新闻搜索/摘要。日历仍通过本地旧授权路径读取，组合后直接播报，不放入这份公开新闻归档。天气查询使用独立会话历史。

搜索只用三家媒体域名；检索必须有真实搜索调用；模型文本中的URL只作为候选，最终须通过域名、原文访问和发布时间验证；直接读取的官方栏目链接也可作为候选；读取原文时逐跳限制重定向域名，不跟随到任意模型提供的网站。没有可验证原文时返回缺项，不伪装成功。公开站点的安全检测、访问限制或页面改版可能导致某一家无可用内容。

## 实现与配置

- `news_briefing.py`：分站检索、原文读取、原文时间检查、摘要、去重、归档、分段组织。
- `runtime.py`：晨报专门处理分支，逐段送入现有 mi TTS。
- `assistant_features.py`：普通调用入口复用同一晨报生成器。
- `mac_features.json`：
  - `briefing_city`: `上海`
  - `briefing_news_sources`: `["36氪", "财经网", "环球网"]`，允许在这三者中选择。
  - `briefing_news_per_source`: `3`，运行时限制为1至3。
  - `briefing_archive_folder`: `<你的笔记库路径>/小爱语音/晨报`
  - `briefing_schedule`: `null`，未启用调度。
  - `briefing_include_reminders`: `false`。

原生辅助程序未改动、未重新编译，不影响已完成的统一授权。
