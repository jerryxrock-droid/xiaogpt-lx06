# 十二条晨报配置

更新：2026-10-19。唤醒小爱后说 **“早报”**。

## 当前规则

- 总目标 **12条**；不承诺来源受限时一定凑满。
- 主来源：**36氪、虎嗅网、财新网**。近24小时内容优先，按来源轮流选取；三家都充足时每家约4条。
- 某来源不足，允许其他来源补位，不再限制每家最多3条。
- 主来源近24小时数量不足时查询备用 **财经网、环球网**；播报和归档保留实际来源名称，不将备用稿件标成主站新闻。
- 先选近24小时；不足再补24至48小时内容，并在播报中说“补充，某月某日”。超过48小时或未来时间不选。
- 每家搜索最多20个候选，结合官方公开栏目链接，最多核对30个原文URL；按来源限制同时读取的请求数量。
- 每轮先选目标数量做摘要、跨站去重，再从剩余候选补选；重复事件过多时有界补选，不无限等待。
- 使用“重点新闻”描述，不承诺已取得官方热度排名。

## 财新与付费内容

财新网（caixin.com）与财经网（caijing.com.cn）是不同来源。财新仅使用原文公开标题、公开导语及可核实发布时间；不读取或绕过付费全文，不借搜索结果猜测付费正文。播报用“公开消息”标明阅读范围，归档写入 `public_preview`。没有公开时间或有效公开信息时跳过。

## 播报与归档

当前只播报新闻：简短条数提示 → 各来源新闻。不再查询或播报天气、不读取或播报日历。也不口播筛选规则、目标条数或归档完成提示；新闻仍保存到Obsidian。

只语音触发，不新增定时任务，不汇总提醒事项。各来源独立分段送入现有小米TTS，仍可能受到小米内容审核影响。原生控制中心没有重新编译或改变授权。

Obsidian：`小爱语音/晨报/`。保存标题、来源链接、发布时间、摘要、公开阅读范围、是否48小时补充；不保存付费全文，也不将本地日历送入新闻搜索或摘要。

## 可维护配置

部署目录 `mac_features.json`：

```json
{
  "briefing_news_sources": ["36氪", "虎嗅网", "财新网"],
  "briefing_news_target": 12,
  "briefing_news_fallback_sources": ["财经网", "环球网"]
}
```

旧的 `briefing_news_per_source` 固定上限已移除。修改配置需重启服务。

2026-10-19：按用户要求移除早报天气与日程环节，保留12条目标、优先媒体和24/48小时补充规则。已测试不会调用天气查询或本地日历接口，104项回归通过。后续已按用户确认执行两分钟速览风格，见下方更新。

## 两分钟速览版（已启用）

2026-10-19：口播与笔记摘要分开生成。每条口播只保留主体、动作和一个关键结果，目标约20至30字；英文名称按近似口播长度计量，纯字符数可能略长。去掉背景分析、影响解读和“值得关注”等套话，保留拟、预计、可能、否认等重要限定。来源每组只说一次；财新只公开标题/导语的阅读范围也每组提示一次。较早的补充新闻仍逐条标明日期。

笔记继续保存标题、来源、发布时间、事实摘要和短句，便于阅读原文。若模型短句不合格，会有界重试，或使用完整短标题；不机械截断句子。仍无法得到合格短句时不冒充已播，口播条数按实际可播条目计算。

实测上一轮12条新闻全部生成可播短句，来源及编号合计约428个字符，预计约两分钟，实际语速由音箱决定。112项自动化回归通过，包括完整短句、英文名长度、单组来源提示、旧闻日期保留和实际播报计数。
